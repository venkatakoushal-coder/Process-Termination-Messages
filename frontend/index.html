Operating System Implementation Architecture
waitpid(-1, &status, WNOHANG)

The C parent process polls child status asynchronously without blocking concurrent child executions. Returning > 0 identifies an exited child PID ready for reaping.

WIFEXITED(status) & WEXITSTATUS(status)

Identifies normal process exit via exit(code) or return from main. Exit status 0 represents standard clean termination.

WIFSIGNALED(status) & WTERMSIG(status)

Detects if a child was killed by an asynchronous POSIX signal (such as SIGTERM=15 or SIGKILL=9), identifying unhandled signal events.

Parent Process Cleanup & Zombie Prevention

Once waitpid() collects the termination status, Linux clears the task struct from the OS process table, preventing memory leaks and defunct zombie states.

Interactive OS Laboratory Scenarios

Execute real, controlled Linux process scenarios to observe and verify fundamental kernel mechanisms: synchronization, signal handling, uncatchable kills, and defunct zombie states.

Scenario 1

Normal Process Completion

Parent forks child processes that execute their sleep workload and terminate cleanly with exit(0).

fork() → sleep() → exit(0) → WIFEXITED → REAPED
Scenario 2

SIGTERM Signal Termination

Parent delivers SIGTERM (15). The child terminates via signal; parent catches it via WIFSIGNALED and extracts WTERMSIG == 15.

kill(SIGTERM) → WIFSIGNALED → WTERMSIG 15 → REAPED
Scenario 3

SIGKILL Force Termination

Parent delivers SIGKILL (9). SIGKILL cannot be caught or ignored; the Linux kernel immediately aborts the process task struct.

kill(SIGKILL) → kernel abort → WTERMSIG 9 → REAPED
Scenario 4

Parent `waitpid()` Synchronization

Spawns 50 child processes with mixed lifetimes. Observe how parent continuously collects terminated children with WNOHANG without stalling.

50 children → asynchronous polling → dynamic reaping
Scenario 5

Controlled Zombie Demonstration

Child terminates immediately with exit(0). Parent intentionally delays calling waitpid() for 6 seconds. Child exists as [ZOMBIE / defunct] in the real Linux kernel until parent reaps it.

exit() → parent delays waitpid() → Z (Zombie) → waitpid() → REAPED
